## تشغيل سريع للتجربة (بدون مفاتيح)

يحتاج Node.js 22 أو أحدث.

```bash
npm install
cp .env.example .env.local      # اترك DATA_BACKEND=memory
npm run init-sheets             # ينشئ كل الجداول في ملف محلي .data/db.json
npm run seed                    # بيانات تجريبية لثلاث شركات
npm run dev                     # افتح http://localhost:3000
```

ادخل بأحد الحسابات التجريبية. كلمة المرور لكلها `Demo@2026`:

| اسم الدخول | الدور |
|---|---|
| `admin@qaswarah.test` | مدير النظام |
| `manager@qaswarah.test` | مدير |
| `buyer@qaswarah.test` | مشتري إعلانات |
| `designer@qaswarah.test` | مصمم |
| `viewer@qaswarah.test` | مشاهد |

هذه الحسابات للتجربة المحلية فقط. لا تشغّل `npm run seed` على الشيت الحقيقي.

لتجربة الاستيراد استخدم الملفات في مجلد `samples/`.

## ربط Google Sheets بحساب خدمة

**1. أنشئ ملف الشيت**

أنشئ Google Sheet فارغًا باسم مثل "Qaswarah Ads Hub". انسخ المعرّف من الرابط، وهو الجزء بين `/d/` و `/edit`:

```
https://docs.google.com/spreadsheets/d/  هذا_هو_المعرّف  /edit
```

**2. أنشئ حساب الخدمة**

1. ادخل إلى [Google Cloud Console](https://console.cloud.google.com/) وأنشئ مشروعًا، أو اختر مشروعًا موجودًا.
2. من **APIs & Services ← Library** فعّل **Google Sheets API**.
3. من **IAM & Admin ← Service Accounts** اضغط **Create service account**، وسمّه مثلًا `ads-hub`. لا يحتاج أي دور.
4. افتح الحساب، ثم **Keys ← Add key ← Create new key ← JSON**. سيُنزَّل ملف JSON. احفظه في مكان آمن، ولا ترسله في أي محادثة.

**3. شارك الشيت مع حساب الخدمة فقط**

افتح الشيت، واضغط **Share**، وأضف إيميل حساب الخدمة (الحقل `client_email` في ملف JSON) بصلاحية **Editor**. اترك الشيت **مقيّدًا** (Restricted)، ولا تجعله "أي شخص لديه الرابط يمكنه التعديل".

> **لماذا لا نجعل الشيت عامًا؟** لسببين. الأول أن Google لا تسمح لأي برنامج بالكتابة في شيت عبر الـ API بدون حساب خدمة أو تسجيل دخول، حتى لو كان الشيت عامًا للتعديل. والثاني أن الشيت العام للتعديل يعني أن أي شخص يصل إليه الرابط يستطيع قراءة أرقام الإنفاق أو تغييرها أو مسحها، دون أي سجل. حساب الخدمة إعداد لمرة واحدة (حوالي 10 دقائق)، وبعده لا يحتاج أحد من الفريق أي حساب Google لاستخدام المنصة.

**4. ضع القيم في `.env.local`**

```
DATA_BACKEND=google
GOOGLE_SERVICE_ACCOUNT_EMAIL=ads-hub@your-project.iam.gserviceaccount.com
GOOGLE_PRIVATE_KEY="-----BEGIN PRIVATE KEY-----\n...\n-----END PRIVATE KEY-----\n"
SPREADSHEET_ID=المعرّف_من_الخطوة_1
```

انسخ `private_key` من ملف JSON كما هو، بين علامتي تنصيص، مع إبقاء `\n`.

**5. أنشئ الجداول**

```bash
npm run init-sheets     # ينشئ 18 تبويبًا بأعمدتها، ويضيف أي عمود ناقص لاحقًا دون حذف بيانات
npm run seed            # اختياري: بيانات تجريبية. لا تشغّله على شيت فيه بيانات حقيقية
```

التبويبات: Companies, Platforms, AdAccounts, Campaigns, AdSets, Creatives, CreativeVersions, CreativeSchedule, DailyResults, ImportBatches, ImportChanges, ColumnMappings, Budgets, Targets, Users, ActivityLog, Settings, ShareLinks.

> لا تغيّر ترتيب الأعمدة أو أسماءها في الشيت يدويًا. الحذف في المنصة "ناعم": الصف يبقى مع `is_deleted = TRUE`.

## الحسابات وكلمات المرور

لا يحتاج الفريق أي حساب Google. مدير النظام ينشئ لكل زميل اسم دخول وكلمة مرور من داخل المنصة.

**أول دخول:** ضع في الإعدادات (`.env.local` محليًا، أو Vercel عند النشر):

```
AUTH_SECRET=...              # أنشئه بالأمر: npx auth secret
ADMIN_USERNAME=admin
ADMIN_PASSWORD=كلمة-مرور-طويلة-وقوية
```

ادخل بهذا الحساب، ثم من **الإعدادات ← المستخدمون والصلاحيات**:

1. اضغط **إضافة مستخدم**، واكتب اسم الدخول (مثل `ahmed.h`) والاسم والدور والشركات.
2. اضغط **توليد** لإنشاء كلمة مرور قوية، ثم **حفظ**.
3. تظهر بيانات الدخول مرة واحدة. انسخها وأرسلها للزميل بطريقة آمنة.

**نصائح**

- أنشئ لنفسك حسابًا عاديًا بدور مدير النظام، واستخدمه يوميًا. احتفظ بحساب `ADMIN_USERNAME` للطوارئ فقط.
- إذا نسي زميل كلمة المرور: افتح حسابه ← اكتب كلمة مرور جديدة ← حفظ.
- كل مستخدم يستطيع تغيير كلمة مروره من القائمة أعلى الصفحة ← **تغيير كلمة المرور**.
- كلمات المرور تُحفظ في عمود `password_hash` في تبويب Users بشكل مشفّر (scrypt)، ولا تُحفظ الكلمة نفسها أبدًا. لا تعدّل هذا العمود يدويًا.
- خمس محاولات خاطئة متتالية تقفل اسم الدخول 15 دقيقة.
- إزالة مستخدم أو تغيير دوره يطبّق فورًا على طلبه التالي.

## النشر على Vercel

1. ادخل إلى [vercel.com/new](https://vercel.com/new) واستورد المستودع `Central-Team-Campaigns`. سيتعرّف على Next.js تلقائيًا.
2. في **Settings ← Environment Variables** أضف هذه القيم لبيئة **Production** (وPreview إن أردت):

| المتغير | القيمة |
|---|---|
| `DATA_BACKEND` | `google` (إلزامي على Vercel، لأن الملف المحلي لا يُحفظ هناك) |
| `GOOGLE_SERVICE_ACCOUNT_EMAIL` | من ملف JSON |
| `GOOGLE_PRIVATE_KEY` | من ملف JSON، الصقه كما هو |
| `SPREADSHEET_ID` | معرّف الشيت |
| `AUTH_SECRET` | ناتج `npx auth secret` |
| `ADMIN_USERNAME` و `ADMIN_PASSWORD` | حساب الطوارئ لمدير النظام |
| `APP_URL` | عنوان الموقع الكامل، مثل `https://ads.qaswarah.com` |

3. اضغط **Deploy**، ثم ادخل بحساب الطوارئ وأنشئ حسابات الفريق.
4. لربط نطاق خاص: **Settings ← Domains**، ثم حدّث `APP_URL` وأعد النشر.

**ملاحظات مهمة**

- **ملفات PDF:** يفتح الخادم صفحة التقرير في متصفح Chromium مدمج ويحوّلها إلى PDF. لذلك يجب أن يكون `APP_URL` صحيحًا. إعدادات الذاكرة والمهلة موجودة في `vercel.json`.
- **حماية النشر (Deployment Protection):** إذا كانت **Vercel Authentication** مفعّلة على نسخ Preview، فلن يستطيع مولّد PDF فتح صفحة التقرير هناك، وروابط المشاركة لن تفتح لمن هو خارج فريق Vercel. نسخة Production على النطاق الرئيسي غير محمية افتراضيًا وتعمل بشكل طبيعي. لتجربة PDF على Preview عطّل الحماية من **Settings ← Deployment Protection**، أو جرّبه على Production.
- **سرعة Google Sheets:** المنصة تحتفظ بنسخة مؤقتة من كل تبويب لمدة 60 ثانية، وتُحدَّث فور أي تعديل من المنصة. التعديلات اليدوية المباشرة على الشيت تظهر خلال دقيقة.

## الأدوار والصلاحيات

| الدور | ما يستطيعه |
|---|---|
| مدير النظام | كل شيء، بما فيه الإعدادات والمستخدمين |
| مدير | كل الشركات: الحملات والتصاميم والاعتماد والميزانيات والتقارير وروابط المشاركة |
| مشتري إعلانات | الشركات المحددة له فقط: الحملات والاستيراد والجدولة، وتقرير أدائه هو فقط |
| مصمم | الشركات المحددة له فقط: التصاميم ونسخها والجدولة. لا يرى الإنفاق أو التقارير |
| مشاهد | قراءة فقط للشركات المحددة له: لوحة التحكم والحملات والتقارير |

## قائمة الفحص الذاتي بعد النشر

ضع علامة على كل بند بعد تجربته على الموقع المنشور:

**الدخول والصلاحيات**
- [ ] ادخل بحساب `ADMIN_USERNAME` وتظهر لوحة التحكم.
- [ ] كلمة مرور خاطئة تظهر "اسم الدخول أو كلمة المرور غير صحيحة".
- [ ] أنشئ لنفسك حسابًا بدور مدير النظام، وادخل به.
- [ ] أضف زميلًا كمشتري إعلانات لشركة واحدة. يدخل ويرى تلك الشركة فقط.
- [ ] غيّر كلمة مرورك من القائمة أعلى الصفحة، واخرج وادخل بالجديدة.
- [ ] أزل الزميل. في طلبه التالي يخرج إلى صفحة الدخول.

**البيانات**
- [ ] أضف شركة من **الشركات**، وتظهر كصف جديد في تبويب Companies في الشيت.
- [ ] أضف حسابًا إعلانيًا وحملة لهذه الشركة.

**استيراد Meta**
- [ ] صدّر تقريرًا من Ads Manager (تقسيم يومي، مستوى الإعلان)، وارفعه من **استيراد Meta**.
- [ ] راجع ربط الأعمدة والمعاينة، ثم احفظ. تظهر النتائج في لوحة التحكم.
- [ ] ارفع الملف نفسه مرة ثانية. الأرقام لا تتضاعف (تحديث وليس تكرارًا).
- [ ] من **سجل الاستيراد** تراجع عن الاستيراد الثاني، والأرقام تبقى صحيحة.

**التصاميم والجدولة والميزانيات**
- [ ] أنشئ تصميمًا، أرسله للمراجعة، واعتمده بحساب مدير.
- [ ] جدوله في التقويم، ثم اسحبه ليوم آخر.
- [ ] أدخل خطة الشهر لشركة، وتظهر وتيرة الصرف في لوحة التحكم.

**التقارير**
- [ ] من **التقارير** نزّل PDF لتقرير مجمّع. يفتح بالعربية والشعار وأرقام الصفحات.
- [ ] نزّل ملف Excel وافتحه.
- [ ] أنشئ رابط مشاركة وافتحه في نافذة خاصة دون تسجيل دخول. ثم ألغه، والرابط يعرض "الرابط غير صالح".

**الإعدادات**
- [ ] غيّر حد "أقل نسبة نقر" واحفظ. التنبيهات في لوحة التحكم تتغير.
- [ ] بدّل اللغة إلى English ثم ارجع للعربية، وجرّب الوضع الداكن.
- [ ] افتح الموقع من الجوال وتنقّل بين الأقسام.

## للمطوّرين

| الأمر | الوظيفة |
|---|---|
| `npm run dev` | التشغيل المحلي |
| `npm run build` | بناء نسخة الإنتاج |
| `npm test` | الاختبارات (Vitest) |
| `npm run typecheck` | فحص الأنواع |
| `npm run lint` | فحص الكود |
| `npm run init-sheets` | إنشاء الجداول والأعمدة الناقصة |
| `npm run seed` | بيانات تجريبية |

```
app/              الصفحات (App Router) و API routes للتقارير
components/       مكونات الواجهة لكل قسم
lib/sheets/       طبقة البيانات: getAll, getById, insert, update, softDelete, bulkInsert, upsertMany
lib/auth/         الأدوار والصلاحيات (permissions.ts)
lib/actions/      Server Actions لكل قسم
lib/data/         قراءات مجمّعة: لوحة التحكم، الحملات، التصاميم، الميزانيات، التقارير
lib/metrics/      حساب المؤشرات من المجاميع (لا متوسط للمتوسطات)، ومؤشرات كل منصة، وإرهاق التصميم
lib/import/       قراءة ملفات Meta وربط الأعمدة والتراجع
lib/reports/      معاملات التقارير، PDF، وروابط المشاركة
messages/         نصوص العربية والإنجليزية
scripts/          init-sheets و seed
tests/            اختبارات الوحدات
```

**قواعد ثابتة في الكود**

- المؤشرات تُحسب دائمًا من المجاميع: CTR = النقرات ÷ الظهور، وليس متوسط نسب الأيام.
- ترتيب الحملات حسب تكلفة النتيجة يشمل فقط أهداف التحويل: Leads و Sales و Messages.
- لا رسوم بمحورين. الصرف والنتائج رسمان متزامنان.
- الأسبوع يبدأ يوم الأحد، والمنطقة الزمنية Asia/Riyadh.

**الهوية:** الألوان في أعلى `app/globals.css` (الكحلي `#0F1B2D`، الذهبي `#C9A227`، الخلفية `#F5F6F8`). الشعار في `public/brand/`. استبدل الملفات بنفس الأسماء.
